# SnapShop — български многопродавачен пазар с AI обяви

Next.js 14 (App Router) · React 18 · JSON файлова база (`data/db.json`) · интерфейс изцяло на български, оптимизиран за телефон.

## Какво има

| Област | Функции |
|---|---|
| AI обяви | Плъзгане на много снимки → разпознаване, **категория и подкатегория**, **марка** (вплетена в заглавие и описание), описание, цена, изрязване на бял фон |
| Уникалност | Описанието се сравнява със съществуващите продукти; твърде сходни се пренаписват, а публикуване на почти идентични се блокира |
| Търсене (3 етапа) | 1) до 50 точни съвпадения · 2) подобни · 3) допълващи (мляко→захар, пирони→чук; чрез вградени двойки, AI и история на поръчките) |
| Странична лента | Дърво на категориите, цена, марка, състояние, наличност, само промоции (на телефон – бутон „Филтри“) |
| Промоции | Бутони −10/20/30/40/50 % → крайната цена се преизчислява навсякъде (каталог, продукт, количка, поръчка) |
| Табло на продавача | Търсене/филтри в собствените обяви, масови промоции, наличност (ниска/изчерпана), ценова листа CSV, реклами, склад |
| Реклами | Приоритет в търсенето · препоръчан в категория · топ банер (начало/категория), за `AD_DAYS` дни |
| Продуктова страница | Първо още от същия продавач, после подобни от други |
| Ценови листи | Продавачът качва CSV; купувачи и продавачи свалят CSV (отваря се в Excel) |
| Групови покупки | Складове с минимална поръчка, жива лента „Текуща сума: X / Y необходими“, ескроу, връщане на парите при неуспех |
| Облачни снимки | S3-съвместим бакет (R2/S3/B2/MinIO); в базата се записва публичният CDN адрес |
| Администрация | `is_admin`; потребители, обяви, съобщения, одобрение на реклами, складове |

## Пускане

```bash
npm install
cp .env.example .env.local     # попълнете SESSION_SECRET и поне един AI ключ
npm run dev                    # http://localhost:3000
```

Минимум: `SESSION_SECRET`. Без AI ключ приложението работи в демо режим (примерни чернови). Първият регистриран потребител е администратор (или `ADMIN_EMAILS`).

### Облачно хранилище за снимки (Cloudflare R2)
1. Създайте бакет, API токен (Object Read & Write) и публичен домейн/`r2.dev` адрес.
2. Задайте `S3_ENDPOINT`, `S3_REGION=auto`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_URL`.
3. Качените снимки получават адрес `S3_PUBLIC_URL/products/<продавач>/<id>.jpg`, който се записва в продукта. Триенето на обява/профил изтрива и обекта.

### Плащания и webhook
Задайте `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`; в Stripe добавете endpoint `/api/stripe/webhook` за `checkout.session.completed` и `checkout.session.async_payment_succeeded`. Без Stripe: поръчките са с наложен платеж, рекламите чакат ръчно одобрение от администратор.

### Групови покупки — ВАЖНО
- Купувачите плащат на **платформата**; при достигнат праг парите се прехвърлят към свързания Stripe акаунт на склада (минус `GROUP_FEE_PCT`), при изтекъл срок се връщат.
- Реално държане на чужди средства и изплащане към трети лица изисква **Stripe Connect** (отделни такси и трансфери), потвърден акаунт на склада и **правна/финансова консултация** (лиценз за платежни услуги, ДДС, общи условия). Кодът е техническа основа, не юридическо решение.
- Без `STRIPE_SECRET_KEY`: в разработка работи **ДЕМО** режим (симулирани плащания, ясно обозначен); в production груповите покупки са изключени.
- Складовете се създават от администратор (в „Администрация → Складове“) и се възлагат на регистриран потребител.

## Честно за състоянието и ограниченията
- **Приложението не е компилирано и пуснато с `next build`/`next dev` в средата, в която е писано** (достъпът до npm регистъра беше блокиран). Затова е възможно да има грешки при първо стартиране — съобщете ги и ще бъдат поправени.
- Тествана е самостоятелно (в Node, без Next) чистата логика: подписване на S3 (спрямо официалните AWS тестови вектори), търсене в 3 етапа, цени и промоции, реклами, CSV внос/износ, ескроу логика (с имитиран Stripe), проверка на webhook подпис, прилика на описания. Страниците/компонентите са проверени само за синтаксис и за съществуване на импортите.
- Само CSV (не `.xlsx`): в Excel „Запиши като → CSV UTF-8“. Поддържа се и Windows-1251.
- Uploadthing не е реализиран; поддържа се всеки S3-съвместим бакет.
- Българските текстове са вписани директно (няма i18n речник). Стари продукти с английски категории остават непроменени.
- AI разширението на търсенето изисква AI ключ; без него се ползват вградените двойки и история на поръчките.
- JSON базата е за малък мащаб; за повече трафик преминете към Postgres.
